# 小红书博主主页采集插件设计

日期：2026-08-29

## 1. 目标

开发一个兼容 Dia 浏览器的 Chrome Manifest V3 扩展。用户在已登录并有权访问的小红书博主主页中点击悬浮按钮，插件自动滚动页面、采集博主账号信息和主页公开作品卡片信息，并在本地导出 Excel 文件。

第一版只采集主页已经公开展示的信息，不逐篇打开作品详情，不采集评论，不调用小红书未公开接口，也不保存账号密码或 Cookie。

## 2. 用户流程

1. 用户在 Dia 中打开一个小红书博主主页。
2. 扩展识别到有效的博主主页后，在页面右下角显示“采集此博主”悬浮按钮；其他页面不显示。
3. 用户点击按钮后，扩展先读取账号信息和当前已加载的作品，再以温和间隔自动向下滚动。
4. 扩展持续识别新增作品、去重并显示实时数量。
5. 页面到底且连续 3 轮等待均未出现新作品时，采集自动完成。
6. 扩展在本地生成 Excel 并触发下载，然后显示采集总数和完成状态。
7. 用户可在采集中随时停止，并选择导出已采集的数据。

切换页面、关闭标签页或点击停止都会结束当前任务，扩展不会在后台继续浏览或采集。

## 3. 功能范围

### 3.1 博主信息

“博主信息”工作表包含以下字段：

| 字段 | 说明 |
| --- | --- |
| 主页链接 | 规范化后的当前博主主页地址 |
| 账号名 | 页面展示的博主名称 |
| 小红书号 | 页面展示的小红书账号标识 |
| 头像链接 | 头像图片 URL，只保存链接 |
| 简介 | 页面展示的账号介绍 |
| IP 属地 | 页面展示时采集；未展示时留空 |
| 关注数原文 | 例如“128” |
| 关注数值 | 转换后的数值，例如 128 |
| 粉丝数原文 | 例如“1.2万” |
| 粉丝数值 | 转换后的数值，例如 12000 |
| 获赞与收藏数原文 | 页面展示的原始文本 |
| 获赞与收藏数值 | 转换后的数值 |
| 已采作品数 | 本次最终去重后的作品数量 |
| 采集时间 | 本地时间，包含时区 |
| 导出备注 | 缺失字段或异常说明 |

### 3.2 作品信息

“作品列表”工作表每篇作品占一行，包含以下字段：

| 字段 | 说明 |
| --- | --- |
| 序号 | 按本次采集顺序生成 |
| 标题 | 主页作品卡片展示的标题；没有标题时留空 |
| 作品链接 | 规范化后的作品详情链接，可点击 |
| 作品 ID | 能从链接或页面数据可靠获得时填写 |
| 作品类型 | 图文、视频或未知 |
| 点赞数原文 | 卡片展示的原始文本，例如“2.3万” |
| 点赞数值 | 转换后的数值，例如 23000 |
| 封面链接 | 封面图片 URL，只保存链接 |
| 导出备注 | 缺失字段或解析异常说明 |

第一版不下载、嵌入或上传头像与封面图片，也不为图片链接请求额外的数据。图片链接失效不影响其他数据导出。

## 4. 技术方案

采用“页面已有结构化数据 + DOM 回退”的混合采集方案：

- 优先读取当前页面已经加载并向页面暴露的结构化数据。
- 对结构化数据中缺失的字段，从当前渲染的账号区和作品卡片补齐。
- 通过正常页面滚动触发后续作品加载，不调用未公开接口。
- 对关键字段使用一组有优先级的兼容选择器，避免单个样式类变化导致全部采集失败。
- 只有在字段来源能够可靠识别时才写入数据；不能确定时留空并记录备注，禁止错位填充或推测。

### 4.1 组件边界

1. **页面识别器**：判断当前 URL 与页面结构是否为博主主页，控制悬浮按钮是否出现。
2. **交互控制器**：管理就绪、采集中、完成、暂停和失败状态，接收开始、停止与重试操作。
3. **账号解析器**：从结构化数据或账号区 DOM 生成统一的博主信息对象。
4. **作品解析器**：从已加载数据或作品卡片生成统一的作品对象，不负责滚动。
5. **滚动协调器**：执行温和滚动、等待页面更新、检测新增作品并判断结束条件。
6. **数据整理器**：规范化链接和计数，按作品 ID 或规范化链接去重，生成缺失字段备注。
7. **Excel 导出器**：在本地生成包含两个工作表的 XLSX 文件并触发下载。

各组件只通过统一的数据对象和任务状态通信。页面结构变化应主要限制在解析器和页面识别器中，不影响滚动、去重或导出逻辑。

### 4.2 去重与数值规范化

作品去重键按以下优先级选择：

1. 可靠提取的作品 ID；
2. 去除跟踪参数和无关查询参数后的规范化作品链接。

计数值保留页面原文，同时转换为便于 Excel 分析的数值。转换支持普通整数以及“万”等页面实际出现的单位；无法可靠转换时数值列留空，原文不丢失。

### 4.3 Excel 输出

- 文件名格式：`账号名_小红书主页_YYYY-MM-DD.xlsx`。
- 工作表顺序：`博主信息`、`作品列表`。
- 链接字段以可点击链接形式写入。
- Excel 生成库随扩展本地打包，不从远程 CDN 加载代码。
- WXT 0.20.27 会将 ExcelJS 连同内容脚本内联；当前构建测得该启动脚本约增加 1.1 MB。导出逻辑仍只在用户请求导出时初始化，但这不是网络分块加载：代码已经随扩展安装并在内容脚本包内。将 Excel 导出移到后台上下文可改变该取舍，第一版不扩大为该架构调整。
- 所有数据在本地内存中处理并导出，不上传到服务器。

## 5. 权限与隐私

扩展仅申请完成任务所需的最小权限：

- 在小红书相关页面运行内容脚本；
- 使用浏览器下载能力保存 Excel；
- 如任务状态需要跨扩展上下文传递，仅在本地扩展存储中保存临时状态。

扩展不读取或保存 Cookie、密码、完整浏览历史和其他网站内容。采集只发生在用户主动点击后的当前标签页，并仅处理用户当前有权访问的公开页面内容。

## 6. 状态与错误处理

### 6.1 状态

- **就绪**：显示“采集此博主”。
- **采集中**：显示当前已发现作品数和“正在加载更多”，提供“停止采集”。
- **完成**：显示最终作品数和“Excel 已下载”。
- **暂停/失败**：说明具体原因，提供“重试”和“导出已有数据”。

### 6.2 结束条件

滚动协调器在接近页面底部时等待页面加载。连续 3 轮等待后作品集合均未增长，且页面仍处于底部，判定为正常完成。每轮使用温和间隔，避免高频操作。

### 6.3 异常策略

- 网络超时或页面未继续加载：暂停任务，保留内存中的已采数据，允许重试或导出。
- 页面出现验证或访问限制：立即停止自动滚动，提示用户处理，不尝试绕过。
- 页面结构无法识别：停止采集并显示字段或区域识别失败，不生成看似完整的错误数据。
- 单个作品字段缺失：保留作品行，将该字段留空并写入备注。
- Excel 生成失败：保留当前任务数据，提示重新导出。

## 7. 兼容性

第一版以 Dia 浏览器当前使用的 Chromium 扩展能力和 Manifest V3 为目标，同时保持对标准 Chrome Manifest V3 环境的兼容。第一版不承诺 Firefox 或 Safari 支持。

## 8. 测试方案

### 8.1 自动测试

- 主页 URL 与页面识别规则；
- 账号字段解析与缺失字段处理；
- 图文、视频和未知类型作品解析；
- “万”等计数单位换算以及无法转换的输入；
- 作品 ID 与规范化链接去重；
- 连续 3 轮无新增的停止条件；
- 工作簿字段、工作表顺序、链接和文件名生成。

解析测试使用脱敏、最小化的本地 HTML/数据样本，不依赖实时小红书页面。

### 8.2 Dia 手工验收

至少覆盖以下场景：

- 小规模账号和几百篇作品的大规模账号；
- 图文、视频以及混合作品主页；
- 账号字段或作品标题缺失；
- 网络变慢、滚动加载中断和用户手动停止；
- 非博主页面不显示悬浮按钮；
- 同一作品重复出现在页面数据中时 Excel 只保留一行。

## 9. 验收标准

1. 在 Dia 中打开有效博主主页时能看到悬浮按钮，其他小红书页面不显示。
2. 点击按钮后无需逐篇打开作品，插件能自动滚动并采集页面已公开的全部作品。
3. 采集过程显示实时数量，用户可以停止、重试或导出已有数据。
4. 正常完成后下载的 Excel 可以打开，并包含 `博主信息` 和 `作品列表` 两个工作表。
5. 账号字段与页面一致，作品无重复，作品链接和封面链接均可点击。
6. 头像和封面只以 URL 保存，不下载、不嵌入、不上传图片。
7. 字段缺失、页面变化或加载异常时有明确提示，不伪造数据，也不丢失已经采集的有效记录。

## 10. 第一版明确不做

- 进入作品详情采集正文、发布时间、标签、收藏数或评论数；
- 采集评论；
- 调用或逆向未公开接口；
- 保存或管理小红书登录凭据；
- 下载、嵌入或上传头像与封面图片；
- 后台定时监控、批量账号队列或历史数据管理；
- Firefox、Safari 专用适配。
