# Dia 手工验收清单

## 安装与加载

- [ ] 在项目根目录依次运行 `npm ci`、`npm run check`、`npm run build`、`npm run zip`；四步均成功。
- [ ] 确认解包扩展目录为 `.output/chrome-mv3/`，压缩包为 `.output/*-chrome.zip`（以 `npm run zip` 输出的实际文件名为准）。
- [ ] 在 Dia 地址栏打开 `dia://extensions`（不同版本若无法打开，可从扩展程序 UI 进入），开启「开发者模式」，选择「加载已解压的扩展程序」，并选中 `.output/chrome-mv3/`。
- [ ] 在非小红书页面、首页、搜索页、单篇笔记页等**非个人主页路由**检查：不应显示采集悬浮 UI，也不得运行采集。
- [ ] 使用已登录账号进入一个可正常浏览的个人主页，确认悬浮按钮出现且处于可开始状态；不要尝试绕过登录、人机验证或访问频率限制。
- [ ] SPA 切换到另一位博主时，若新 URL 已出现但页面资料尚未刷新，悬浮按钮应暂不出现；待当前路由的资料结构就绪后才出现，且不得混入上一位博主的数据。
- [ ] 仅 DOM 资料页必须同时具备与 URL 一致的显式用户 ID/主页链接、可识别的资料信息和作品容器；资料尚未加载、身份冲突或作品容器缺失时不得出现悬浮按钮。

## 采集流程

- [ ] 点击开始后，确认计数器随发现的去重作品数量更新，页面会自动向底部滚动。
- [ ] 点击停止，确认显示已收集的部分结果并可导出；再次开始或重试后不丢失已确认的内容。
- [ ] 正常到底后，确认经过稳定轮次自动完成并可以导出。网络慢时等待页面加载，而不是通过刷新、脚本或其他方式绕过限制。
- [ ] 在采集中触发页面 SPA 路由切换，确认采集被取消；切换前的陈旧结果不得触发下载。
- [ ] 出现登录提示、人机验证、验证码或访问频繁提示时，确认采集暂停/报错并保留部分结果；仅在用户自行完成网站要求的验证后点击重试。

## 导出内容核对

- [ ] 导出的 XLSX 有且只有「博主信息」与「作品列表」两张表。
- [ ] 「博主信息」核对主页链接、账号名、小红书号、头像链接、简介、IP 属地、关注/粉丝/获赞与收藏的原文和数值、已采作品数、采集时间、备注。
- [ ] 「作品列表」核对序号、标题、作品链接、作品 ID、图文/视频类型、点赞原文和数值、封面链接、备注；主页、作品和封面 HTTPS 链接均可点击。
- [ ] 头像和封面仅以 URL 导出：不下载图片、不把图片嵌入 XLSX、不上传任何图片或资料。
- [ ] 多次出现同一作品（相同作品 ID/规范化链接）只保留一行；检查标题、类型、点赞和封面按既定合并优先级补全。

## 覆盖场景

- [ ] 小型主页：少量作品，快速完成并导出。
- [ ] 大型主页：大量作品，计数与滚动持续工作，最终无重复行。
- [ ] 图文与视频混合主页：类型和封面链接均正确。
- [ ] 对页面未明确标注媒体类型的作品，导出类型应为「未知」；封面图片本身不能作为图文证据。
- [ ] 同一作品若出现明确但相互矛盾的图文与视频证据，类型应为「未知」并保留「作品类型证据冲突」备注；后续加载不得覆盖该保护状态。
- [ ] 缺少标题、封面、计数或简介的主页：空值及导出备注合理，不阻塞其余数据导出。
- [ ] 慢网络：加载期间不误报完成，停止和重试仍可用。
- [ ] 需要验证/访问频繁：不尝试绕过；完成网站自身验证后再由用户重试。

## 隐私、范围与排障

- [ ] 采集范围仅为当前已登录会话中、当前个人主页可见的资料和作品元数据；不读取或导出 Cookie、浏览历史、私信等无关数据。
- [ ] 若按钮未出现，先核对当前 URL 是否为个人主页、扩展是否已启用，并重新加载该标签页。
- [ ] 若没有新作品或一直未完成，检查网络和页面是否已经到底；可停止后导出部分结果，恢复可见内容后再重试。
- [ ] 若导出未下载，确认采集仍在同一主页路由且浏览器允许下载；SPA 路由变化后的旧任务不会下载，这是预期保护行为。
- [ ] WXT `0.20` 的实测构建行为：ExcelJS 被打包进约 `1.12 MB` 的 content script，但仅在用户导出时惰性初始化；扩展不加载远程脚本。
